# Развёртывание

Целевая схема продакшен-развёртывания:

- Ubuntu server;
- Nginx как публичный HTTPS reverse proxy;
- Gunicorn как WSGI-сервер Python-приложения;
- Flask-приложение в директории `/opt/peredacha`;
- пользовательская systemd-служба для Gunicorn;
- Let's Encrypt сертификаты для HTTPS.

Рекомендуемая последовательность развёртывания:

```bash
cd /opt/peredacha
git pull

python3 -m venv venv
./venv/bin/pip install -r requirements.txt

sudo cp deploy/nginx-rate-limit.conf /etc/nginx/conf.d/peredacha-rate-limit.conf
sudo cp deploy/nginx-akvilon-peredacha.conf /etc/nginx/sites-available/peredacha.conf
sudo ln -sf /etc/nginx/sites-available/peredacha.conf /etc/nginx/sites-enabled/peredacha.conf
sudo nginx -t
sudo systemctl reload nginx

mkdir -p ~/.config/systemd/user
cp deploy/gunicorn.service ~/.config/systemd/user/gunicorn.service
systemctl --user daemon-reload
systemctl --user enable --now gunicorn.service
```

Gunicorn запускается от обычного пользователя, который установил пользовательскую службу, без `User=nginx` и `Group=nginx`. Служба слушает только `127.0.0.1:8000`.

Nginx должен быть единственной публичной точкой входа в Flask-приложение. Прямые порты Flask/Gunicorn, например `5000` или `8080`, не должны быть доступны из интернета.

Рекомендации по базе данных:

- на стадии тестирования допустим SQLite;
- для промышленной эксплуатации рекомендуется MariaDB;
- MariaDB должна слушать только `127.0.0.1` или приватную сеть;
- порт `3306` не должен быть доступен из интернета.
