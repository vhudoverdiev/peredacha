# Архитектура

CRM построена как серверное Flask-приложение с HTML-шаблонами.

Схема обработки запроса:

```text
Браузер пользователя
  -> HTTPS
  -> Nginx reverse proxy
  -> Unix socket Gunicorn
  -> Flask-приложение
  -> SQLAlchemy models
  -> база данных
```

Основные директории и файлы:

- `app/routes.py` — маршруты, страницы и бизнес-логика;
- `app/models.py` — модели базы данных SQLAlchemy;
- `app/forms.py` — формы WTForms;
- `app/templates/` — HTML-шаблоны Jinja;
- `app/static/` — CSS, JavaScript, service worker и статические файлы;
- `app/services/` — сервисная логика для Excel, PDF, документов, синхронизации и задач;
- `deploy/` — файлы развёртывания Nginx, Gunicorn и systemd;
- `tests/` — автотесты;
- `migrations/` — миграции Alembic/Flask-Migrate;
- `uploads/` — загружаемые файлы;
- `exports/` — сформированные выгрузки;
- `instance/` — локальные runtime-файлы и база SQLite.

Основные сущности данных:

- объекты/проекты;
- квартиры и коммерческие помещения;
- пользователи и роли;
- пункты работ;
- задачи/замечания;
- подрядчики;
- заявки на материалы и списания;
- замеры стекла;
- журналы синхронизации и конфликтов;
- журналы удалений;
- события безопасности;
- посещения сайта и отчёты об ошибках.

Модель доступа:

- пользователи входят по логину и паролю;
- пароли хранятся в виде salted password hash, не в открытом виде;
- роли ограничивают доступ к разделам и действиям;
- пользователи могут быть ограничены конкретными объектами;
- доступ к записям проверяется на сервере, а не только скрытием кнопок в интерфейсе.
